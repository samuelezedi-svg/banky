Major Areas for Improvement 
1. Expand the Dataset
The evaluation uses only 120 URLs, with 45 phishing URLs. A much larger and more diverse dataset should be used to demonstrate that the system performs well beyond a controlled test environment.
2. Use More Real-World Phishing URLs
The study relies heavily on synthetically generated phishing URLs. Testing with real phishing URLs from reliable threat-intelligence sources would provide stronger evidence of practical effectiveness.
3. Improve Punycode/Homograph Detection
One phishing URL was missed because the system does not currently decode Punycode. This is an important weakness that should be addressed because attackers can use visually similar characters to impersonate legitimate domains.
4. Clarify the Performance Results
The paper reports a 125 ms total response time in the latency table but later mentions 170 ms. These figures should be reconciled and the testing conditions clearly explained.
5. Strengthen the Evaluation Methodology
The study should explain more clearly how the URLs were selected, how the heuristic thresholds were determined, and how the testing was conducted. This would make the results easier to reproduce and validate.
6. Test Against More Attack Types
Future evaluation should include a wider range of phishing techniques, including sophisticated typosquatting, URL obfuscation, redirect attacks, domain impersonation, and homograph attacks.
7. Improve Webpage Content Analysis
The current system examines webpage content and suspicious terms such as BVN and OTP. This could be expanded to include forms, page structure, JavaScript behaviour, redirects and other characteristics associated with phishing pages.
8. Conduct User Usability Testing
The study should involve actual users to determine whether the warnings are understandable, whether users respond appropriately to alerts, and whether the extension affects their browsing experience.
9. Improve Threat-Intelligence Updating
The system would benefit from automatic updating of its blacklist/whitelist and threat-intelligence information rather than relying primarily on locally stored information.
10. Clarify the System Architecture
The document describes the system as client-server in one section, while another section states that detection is performed locally without a backend. This architecture should be clearly explained and made consistent throughout the document.
11. Improve Academic Presentation
The paper contains some grammatical errors, typographical mistakes and inconsistencies. Figures, captions, tables and terminology should be carefully reviewed before final submission.
12. Strengthen the Discussion of Limitations
The authors acknowledge that the dataset is synthetic and curated, but this limitation should be emphasized more strongly when interpreting the reported 99.17% accuracy, since the result may not represent performance against diverse real-world phishing attacks.
